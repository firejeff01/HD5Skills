# 送驗收前站上關卡（onsite-gate）

> **適用對象**：主對話。部署到測試環境之後、改工單「待驗收」／通知 PM 之前**必跑**。不派代理（要實機操作）。
> **緣由**：回頭整理「我們的測試全綠、之後才被 PM 或獨立審查抓到」的事件，**最大宗是只在真實站台／真實資料才出現的問題**，
> 其次是畫面版面與非同步載入時序（模擬環境看不到）。典型例子：測試替身的欄位名與真實資料不同，幾百個測試全綠、實機一律走空結果；
> 站台的防偽欄位名不是框架預設值，兩張工單各踩一次；測試環境的主檔只有單一年度，換年度才現形。
> TDD 驗的是「我們自己造的世界」。這道關卡只補一件事：**送驗收之前，在真的站台上用真的資料走一遍。**

專案的站台網址、部署方式、版本探針、平台契約表等**專案事實**寫在該 repo 的 `AGENTS.md`；本 skill 只講方法。

---

## 一、在流程中的位置

```
實作完成 → 獨立驗收（hd5-review，只修 P1）→ 合併到測試分支 → 部署測試環境 → 【站上關卡】→ 結案報告（hd5-case-report）／工單待驗收／通知 PM
                                                                         │
                                                                         └─ 不通過 → 修 → 重新部署 → 重跑本關卡（輪次 +1）
```

- **不取代獨立驗收**（`hd5-review`）：獨立驗收看程式，本關卡看站上的結果。兩個都要。
- **不取代 PM 的 UAT**：本關卡是開發自驗，只產一份 md；目的是讓 PM 驗收時不再抓到「站上一跑就壞」的問題。
- 修正如果動到程式，要不要再送獨立驗收，照原本規則（P1 修正要送）。

## 二、前置：確認站上跑的是這一版

0. 🔴 **先跑 `AI_Service/hd5-tools/verify-map-check.ps1`**：功能地圖（`AI_Service/verify/`）不合格就標 `受阻`，先補地圖（`hd5-verify`）。
   之後的驗證**照功能地圖的「怎麼操作」走**；功能地圖的「體檢」做完即涵蓋下列 2～3 項的大部分檢查。（守衛：verify-map-check.ps1）

量到舊產物是最常見的假綠，先確認再開始：

1. **本案 commit 已全部進部署分支**（測試分支名見 `.claude/workflow.json` 的 branches）：
   ```bash
   git cherry -v <測試分支> <本案分支> $(git merge-base <本案分支> <開發分支>)
   ```
   全部是 `-` 才算進去了。出現 `+` 不一定是沒進：用 diff 套入或手修衝突進去的 commit，內容不同就會判成 `+`，
   要用 `git diff <本案分支> <測試分支> -- <該 commit 動到的檔>` 確認。**不要只用 `merge-base --is-ancestor` 判斷**
   （測試分支若常用 cherry-pick，祖先關係會誤判；判斷「已進」要比內容）。
2. **站上跑的確實是含本案的版本**。優先用**唯讀行為探針**：找一個「舊版與新版結果不同、而且不需要寫入」的操作，
   在站上做一次看結果（例：開某個編輯頁讀一個隱藏欄位，舊版是 0、新版是正確值）。
   找不到這種操作時，才退回核對部署回報的 commit 或站台上的建置產物；站台檔案讀不到就標 `受阻`，不要猜。
   報告裡寫明用的是哪一種方法。
3. **有前端建置產物**：站上的產物要對應這次建置（例如資源清單／入口檔雜湊與本機同一 commit 的建置相同；怎麼比見 AGENTS.md）。
4. **有部署腳本／資料庫變更**：確認已在測試環境執行，而且結果符合預期（查一下表／欄位／資料筆數）。

任一項不符 ⇒ 狀態標 `受阻`，先處理部署，不要開始驗。

## 三、帳號與資料

- 用**開發自測帳號**，不要用 PM 正在驗收的帳號（會把對方踢下線）。
- 用共用帳號（自動登入之類）前，先詢問其他正在跑的 session 有沒有在用。**詢問送不到或沒人回** ⇒ 不要自己當作同意，改問使用者：
  由使用者用開發自測帳號登入，或使用者確認後才用共用帳號。測試環境密碼不由 AI 代打。
- 會改共用帳號狀態的操作（例如切語系會改帳號的偏好設定）同樣影響其他 session，沒有必要就不做，在報告裡標 `未驗證` 並寫原因。
- 🔴 **不造測試資料**。驗收資料由 PM 準備。缺資料的項目標 `未驗證`，原因寫「需要什麼樣的資料」，之後放進給 PM 的留言。
  （守衛：無（缺資料時是否自己造資料、寫入前有沒有問使用者，屬判斷））
- 能用唯讀方式驗的就不寫入（開頁讀值、讀隱藏欄位、資料庫只跑查詢）。必須寫入時只做本案驗收項目需要的，
  **要在 PM 驗收用的真實資料上寫入，先問使用者**；寫了什麼要記在報告裡（哪個帳號、哪筆資料、怎麼還原）。
- 會寫共用資料的自動化 E2E，沒有明確允許就不跑（專案的允許開關見 AGENTS.md）。

## 四、必驗 A：驗收項目逐條

驗收基準優先序：工單驗收表（定案版）→ PM 需求文件與其答覆檔（`hd5-spec-html` 產物）→ 質詢拍板紀錄（`hd5-grill` 的 `grill-*.md`）。
沒有 spec 的 Bug 單：以交付留言裡的「請驗收」步驟，加上留言裡承諾的修正行為（例如「就算從少帶參數的網址存檔也不會再清掉」）為準，兩者都要列成驗收項目。

每一條都要在站上**實際操作到最終結果**（存檔後重新載入看值、匯出後打開檔案、送出後看資料庫或清單），
不是只看到按鈕或畫面出現。**元素都在，不代表功能會動。**

有雛形的案子：雛形每張圖對應的頁面與狀態都要實機截圖、並排比對，差異列給使用者決定。

## 五、必驗 B：平台契約清單

平台契約＝「靜態看不出來、單元測試也測不到」、只有在真的站台上才會現形的平台特性。
🔴 **每個專案在 `AGENTS.md` 定義自己的平台契約表**，每列寫清楚四件事：**類別、適用條件、站上怎麼驗、漏掉的後果**。（守衛：無（契約內容依專案而定，要靠人判斷））
本關卡對該表**逐項判斷適用與否**，適用就要在站上驗一次；不適用寫「不適用＋理由」。

AGENTS.md 還沒有這張表 ⇒ 先用下面的通用類別跟使用者把表補起來（`hd5-onboard` 也會引導），再跑本關卡。
專案沒有某類就在表上寫「本專案不適用＋理由」，不要默默刪掉。

| 通用類別 | 典型適用條件 | 要在站上確認的事 |
|---|---|---|
| 表單防偽 | 新增或修改會寫入的請求（表單送出、非同步請求） | 在站上實際送出一次，不能被防偽機制擋下；**以站上實送結果為準**，不以框架預設值推論 |
| 權限 | 新增入口、動作、按鈕 | 用**沒有該權限**的帳號（或改網址直打）試一次要被擋；有權限的帳號要能用 |
| 多租戶／範圍參數 | 網址或表單帶租戶、組織、節點等範圍識別 | 範圍參數沒有被靜默退化成預設值（後果常是授權被跳過、資料整組讀不到） |
| 語系 | 有顯示字串、或查詢以語系過濾 | 至少切一個非預設語系看一次；以語系分列的資料要用該語系那一列 |
| 真實資料值域 | 有年度、期別、類別、單位、代碼等選項或條件 | 挑站上**最舊與最新**的資料各看一次；有空值、已刪除引用、特殊格式（前綴、大小寫、單複數）的也看一次 |
| 資料形狀與替身 | 測試用了替身／假資料 | 站上撈一筆真實資料，對照替身的欄位名和型別 |
| 相依注入與設定 | 新的服務、新的設定鍵 | 在站上**實際觸發到那個服務的動作**（不是只看列表頁）；新設定鍵要確認測試環境已設 |
| 畫面外觀 | 改了版面、元件、彈窗 | 與原版並排截圖：高度、捲軸、標題、關閉鈕要能按 |
| 首屏狀態 | 畫面初始值來自非同步資料或其他元件 | **不操作**，直接看剛載入的畫面值對不對；再重新整理一次 |
| AI 輸出 | 有 LLM 產生的內容（問答、推薦、辨識） | 從站上真實紀錄挑真實輸入回放一批，不要只跑自己寫的題目 |

每類的**具體驗法**（設定在哪、欄位叫什麼、哪張表存紀錄）屬專案事實，寫在 AGENTS.md 的平台契約表，不寫進本 skill。

## 六、產物：`qa/onsite-gate_R{n}.md`

放在 `AI_Service/spec/<案名>/qa/`。固定格式（`## A. 驗收項目` 標題與 A 表欄位名是工具檢查的依據，不要改）：

```markdown
# {案號} 送驗收前站上關卡 R{n}

- 日期：YYYY-MM-DD HH:mm
- 站台：{URL}｜部署 commit：{commit}｜本案 commit 進部署分支：git cherry 全 `-`（或：`+` 項已用 diff 確認）
- 版本確認方法：唯讀行為探針（{做了什麼、看到什麼}）／部署回報 commit／建置產物比對
- 前端建置產物：相符／不適用｜部署腳本／資料庫變更：已執行並確認／不適用
- 帳號：{開發自測帳號}

## A. 驗收項目
| 項目 | 功能 | 結果 | 證據 | 備註 |
|---|---|---|---|---|
| AC-1 … | {功能編號} | Pass／Fail／未驗證／不適用 | `AC-1_存檔後重新載入.png`／查詢：… | 未驗證要寫缺什麼資料 |

## B. 平台契約
| 類別 | 適用 | 結果 | 證據 |
|---|---|---|---|
| {AGENTS.md 平台契約表的類別} | 是／否（理由） | Pass／Fail／未驗證 | … |
（AGENTS.md 表上的類別全部列出，不適用也要列）

## 寫入紀錄
（沒有寫入就寫「無」）

新發現：0 筆
總結：通過
```

- **通過**＝A、B 兩表都沒有 Fail。`未驗證` 可以有，但要寫原因，而且要列進給 PM 的留言（「以下項目需要您準備 … 資料才能驗」）。
- **不通過**＝A 或 B 有任何 Fail。修正後重新部署，重跑下一輪 `R{n+1}`。
- **受阻**＝沒有 Fail，但關卡本身做不完：站上不是這一版、站台錯誤或停擺、帳號或環境問題讓必驗項沒辦法操作。
  寫 `總結：受阻（缺 X）`，補齊後重跑**同一輪** `onsite-gate_R{n}b.md`（證據放 `onsite-gate_R{n}b/`），不算一次不通過。
  ⚠ 缺 **PM 的測試資料**不是受阻：照上一條標 `未驗證`、可以通過、列給 PM。
- **最後一行固定是 `總結：通過`、`總結：不通過` 或 `總結：受阻（缺 X）`**，方便腳本與人工檢查；工單閘只放行通過。
- `新發現：` 一行一定要寫，0 筆也要寫（這次發現、但不屬本案驗收項目的問題，寫進入帳清單，不要只留在對話裡）。
- 截圖放同目錄 `onsite-gate_R{n}/`。
- 🔴 **「功能」欄**填 `AI_Service/verify/features/` 的檔名（可多個，用「、」分隔）；地圖裡沒有這次動到的功能 ⇒ **先補功能檔**。
  只有「不適用」可填 `—`。（守衛：verify-map-check.ps1）
- 🔴 **Pass 必須有證據**：證據檔名（檔案要真的在 `onsite-gate_R{n}/` 或 `qa/`），或內嵌 `查詢：`／`API：`／`畫面值：`。
  只寫「OK」「已確認」會被擋。（守衛：verify-map-check.ps1）
- 這次踩到、地圖沒寫的坑，當輪寫進對應功能檔的「地雷」（維護循環，見 `hd5-verify`）。
- 自查：`AI_Service/hd5-tools/verify-map-check.ps1 -Onsite AI_Service/spec/<案名>/qa/onsite-gate_R{n}.md`（工單閘跑的是同一套）。

## 七、改工單待驗收前的檢查

改「待驗收」、上傳結案報告、發通知之前，確認：

1. `qa/` 下獨立驗收結果（`hd5-review` 的結果檔）最新一輪最後一行是 `總結：通過`
2. `qa/onsite-gate_R{n}.md` 最新一輪最後一行是 `總結：通過`，而且報告裡的部署 commit 跟現在站上的一致
   （關卡跑完後又重新部署，就要重跑）
3. 給 PM 的留言稿有列出全部 `未驗證` 項目與需要的資料

三項都對才進結案（`hd5-case-report`）與改工單狀態。有工單系統時（AGENTS.md／`.claude/workflow.json` 的 tracker），
工單閘會自動再檢查 1、2 兩項，以及功能地圖合格、A 表每條對到功能編號、Pass 有證據檔。
改工單、發通知屬對外動作，照 `hd5-workflow`「對外動作由人決定」：先讓使用者看、同意才做。

## 八、常見誤區

| 誤區 | 正確 |
|---|---|
| 「單元測試、獨立驗收都過了，站上應該沒問題」 | 漏網事件最大宗正是這種情況 |
| 看到畫面出來就算 Pass | 要走到最終結果（存檔後重新載入、匯出後打開檔案） |
| 缺資料就自己在共用資料庫造一筆 | 標 `未驗證`，把需要的資料寫進給 PM 的留言 |
| 契約清單只列適用的 | 表上全列，不適用要寫理由，否則看不出有沒有判斷過 |
| 修完小問題直接通知 PM | 修正要重新部署，重跑關卡（輪次 +1） |
| 讀不到站台檔案就跳過版本確認 | 改用唯讀行為探針；兩者都做不到才標 `受阻` |
| 詢問其他 session 沒回應就當作可以用共用帳號 | 送不到或沒回應時問使用者 |
| 依框架預設值推論「防偽／設定應該沒問題」 | 以站上實送、實際觸發的結果為準 |

相關：`hd5-workflow`（流程位置）、`hd5-review`（上一道關卡）、`hd5-verify`（功能地圖、證據、地雷維護）、
`hd5-case-report`（下一步）、`hd5-no-hallucination`（查不到就說查不到）。
