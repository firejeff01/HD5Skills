# hd5-no-hallucination：文件未定義處理與「文件有寫≠假設成立」

> 適用對象：所有角色（pm／sa／實作代理／qa）
> 本 skill 只規範兩件模型不會自動對齊團隊習慣的事：**問題清單的格式**（第三節），以及
> **什麼時候該停下來問、而不是選一個合理解讀**（第七節）。
> 「不腦補、不擴範圍」是基本紀律，這裡只留一句話版本，節號固定以維持其他 skill 的引用。

## 一、核心原則：依據來源

所有產出內容必須有明確依據，依據來源**只能是**（路徑相對 `AI_Service/spec/<案名>/`）：

| Agent | 允許的依據來源 |
|---|---|
| pm-expert | `case_spec_content/spec_*.md` 需求文件、`spec_*_answer*.html` 回填、使用者明確補充 |
| sa-expert | `pm/*.feature`、`pm/spec_*.html`、`pm/grill-*.md`、專案現有程式碼掃描結果、唯讀資料庫實查 |
| 後端實作代理 | `sa/**/*.feature`、`sa/` 的步驟定義（Step Definitions）、`sa/grill-*.md`、專案現有程式碼 |
| 前端實作代理 | `sa/*`、前後端資料契約、既有前端元件與其註冊處、改造前畫面的比對基準 |
| qa-expert | `sa/*.feature`、`sa/` 的步驟定義、`sa/grill-*.md`、專案現有程式碼 |

（實作代理有哪些見 `.claude/workflow.json` 的 implementers；各技術的檔案慣例見本專案 AGENTS.md。）

訓練資料中的「常見做法」、相似系統的慣例、推測「應該會有」的功能，都不是依據。

## 二、嚴禁腦補

找不到依據的業務邏輯、Scenario、欄位名、驗證規則、流程分支，一律不自行填入，改走第三節提問。

## 三、文件未定義時的處理

當需求文件／上游文件／專案程式碼中**找不到明確依據**時，停下來提出問題清單，不填「看似合理」的內容。

### 問題清單格式（強制）

```
⚠️ 以下項目在 {來源} 中未明確定義，請確認後再繼續：
Q-01. {問題描述} → 請問應該 {選項A} 還是 {選項B}？
      建議：{A/B}——{一句話理由}
Q-02. {問題描述} → 文件中未提及，是否需要納入？
      建議：{是/否}——{一句話理由}
...

（請逐一回覆後，將繼續執行）
```

- 🔴 **每題必附建議答案**（選擇題化）：回覆人從「寫申論題」變成「勾選擇題」，
  回填率與速度都會提升。**建議≠定案**——未回覆前一律 `[待確認]`，不得因建議合理就當已回答。（守衛：無（題目品質要靠人判斷；可列進專案 guard-backlog 當機械化候選））
- 提問前先查證：能從 codebase／資料庫／既有文件（含 `spec_*_answer*.html`、`grill-*.md`、
  `CONTEXT.md`、`docs/adr/`）查到答案的不許問，查了附證據。
  查不到才有資格變成問題（詳見 `hd5-grill` 第三節鐵律 2）。
- 編號 Q-XX 跨輪不重編，與 grill 質詢輪、Open Questions HTML（`hd5-spec-html`）共用同一套編號。
- 主對話把問題轉問使用者時，照 `hd5-workflow`：一題一題問、給選項。

### 各角色問題清單依據來源

| Agent | 「來源」應寫 |
|---|---|
| pm-expert | 「需求文件」 |
| sa-expert | 「PM 文件與專案結構」 |
| 實作代理（後端／前端） | 「SA 文件與專案結構」 |
| qa-expert | 「SA 文件與專案結構」 |

## 四、不擴充範圍

只產出明確出現在文件中的範圍。唯一例外：qa-expert 的 OWASP Top 10 安全測試為強制涵蓋，不依賴文件提及。

## 五、忠實還原業務語言

保留需求文件中的業務術語，不自行簡化或替換；工程師版 Gherkin 與步驟定義的註解仍要讓工程師讀得出業務意圖。

## 六、已寫出但缺依據的內容

在文件中標 `⚠️ TODO: 此項目缺乏文件依據，待使用者確認`，列入問題清單，使用者回覆前一律 `[待確認]`，不得清除。

## 七、文件有寫 ≠ 假設成立（主動質詢的觸發）

第三節是**被動觸發**（文件未定義才問）。但顆粒度缺口常常是
「文件有寫大方向、承重細節沒定」——值域、預設值、衝突處理、舊資料相容。
遇到下列情況，**不要自行選一個合理解讀**——pm／sa 階段直接進入強制質詢輪，
實作代理／qa 則建議使用者啟動質詢輪（方法與範圍閘見 `hd5-grill`）：

1. 同一句需求存在兩種以上實作解讀，且選錯的返工成本高
2. 涉及資料模型、權限、多語系、舊資料相容的決策，文件只寫了正常路徑
3. 你發現自己正在寫「應該是…」「通常會…」開頭的推理
