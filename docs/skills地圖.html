每個 skill 在做什麼

自動＝輪到它時 AI 會自己用。你叫它＝只在你說出口時才用。

hd5-onboard

起手你叫它

把工作流導入一個 repo：掃描專案、讀懂架構、一題一題問你，再產生這個專案自己的規則檔。

誰用
主對話，每個專案導入一次；套件 -Update 後合併代理檔的衝突
怎麼叫
導入工作流掃描專案架構更新代理
產出
AGENTS.md、CLAUDE.md、.claude/agents/、.claude/workflow.json、功能地圖骨架、AI_Service/onboard/ 導入紀錄
把關
check-onboard.mjs：分支沒問、還有待問題、規則沒有去向、產物被 .gitignore 忽略都會擋

hd5-workflow

全程自動

流程總綱：接到需求就判定路線（四角色／PM 端已完成／小問題），照路線派角色、過關卡、結案。

誰用
主對話
何時
接到需求、工單、bug；問「這案子要派誰」「能不能跳過 SA」時
產出
spec_001.md 文末的「路線：…，高風險：…，理由：…」
工具
所有關卡工具和 hook 都隨它裝進 AI_Service/hd5-tools/

hd5-workitem

建案／結案自動

Azure DevOps 工單工具：讀工單建案、看留言、留言、指派、改狀態、上傳結案報告。

誰用
主對話；只在 tracker.type 是 azure-devops 時安裝
怎麼叫
貼工單網址改成待驗收在工單留言
產出
AI_Service/spec/<案名>/（標題、描述、圖片、附件）
把關
工單閘：改「待驗收」或上傳報告前，自動檢查獨立驗收、站上關卡、功能地圖、每個 Pass 都有證據，並對審過的 diff 自動跑密鑰掃描。留言和改狀態要你同意

hd5-spec-html

需求自動

把要給需求方回答的問題做成單檔 HTML 問卷。對方在瀏覽器勾選後儲存答覆，再轉回 Markdown 給 SA 和實作讀。

誰用
pm-expert 出題；主對話傳送、回收；sa 和實作代理讀答覆
何時
有問題要交給 PO、BA、客戶這類不看程式碼的人時
產出
pm/spec_{號碼}.html、pm/spec_{號碼}.questions.json，以及回收的 *_answer*.html
備註
可離線開，圖片內嵌。可選擇上傳工單附件、用 Teams 桌面版傳檔（限 Windows）

hd5-grill

需求與設計PM／SA 自動

質詢輪：把案子還沒決定的地方攤成決策樹，先查證再提問，附建議答案，一直問到每個分支都拍板。

誰用
pm-expert、sa-expert 一律自動跑；實作和 QA 只在你說出口時跑
怎麼叫
grill 我質詢這份設計
產出
<角色目錄>/grill-{主題}.md（拍板紀錄，效力等同需求答覆）；可沉澱 CONTEXT.md 詞彙表、docs/adr/
重點
八個標準分支，外部系統案另加第九分支；SA 另加第十分支「設計形狀」：資料形狀、領域規則放哪、邊界、冪等、共用狀態、重新設計還是接上去，重要決定列 2～3 個方案並排比較
把關
質詢閘 validate-grill-gate.ps1：質詢紀錄沒收斂，就不准派下一個角色；SA 的紀錄沒有「設計形狀」小節只警告、不擋；有警告時先印一行摘要（共幾項、哪幾類），再逐項編號

hd5-no-hallucination

全程自動

文件沒定義的事不腦補，改列問題清單。格式固定，每題附建議答案，跨輪用同一套 Q 編號。

誰用
所有角色
何時
上游文件找不到依據、發現自己在寫「應該是…」「通常會…」、同一句需求有兩種讀法時
產出
各角色的待確認清單（Q 編號）；嚴重到要決策時轉 hd5-grill

hd5-tdd

實作自動

紅綠燈紀律：QA 先交會失敗的測試，而且要為對的原因失敗；實作只寫讓它轉綠的最少程式；最後用 mutation 證明測試真的抓得到錯。

誰用
實作代理、qa-expert
何時
寫產品程式之前、寫測試時、判斷「這組測試算不算數」時
產出
qa/{功能名稱}-tdd-log.md（紅燈證據、綠燈、mutation 結果）
重點
實作不准改 QA 的測試；跑之前先確認測試母體真的收得到東西（少跑不會報錯）

hd5-verify

全程自動

像使用者一樣驗證：照功能地圖把系統開起來，走真實使用者的路徑操作到最終結果，留證據、清理。也規定回報的寫法；效能類數字要先說出瓶頸、排除量到別的東西，才能回報。

誰用
所有角色
何時
開工前、每完成一條驗收條件、獨立驗收核對證據、站上關卡、回報進度時
產出
AI_Service/verify/features/<編號>.md（功能地圖）、證據檔
把關
verify-map-check.ps1：地圖有佔位符、驗收項目對不到功能編號、Pass 沒有證據都會擋

hd5-review

驗收自動

獨立驗收：開發完、合併前，交給沒參與開發的第三方唯讀審查整案的 diff 和行為證據。

誰用
主對話寫委託；有 Codex 用 Codex，沒有就派全新的 Claude 子代理（不能 fork）
怎麼叫
送獨立驗收
產出
qa/獨立驗收委託_R{n}.md、qa/{Codex|Claude}驗收結果_R{n}.md
規則
委託只給事實、不給結論。總結只有三種：通過／不通過（P0 n／P1 n／P2 n）／受阻（缺 X）。只修 P1；受阻補齊後重送 R{n}b。除了驗收項目和證據，也審設計品質（防護是否蓋住根因、規則是否散成條件判斷、舊 API 有沒有留著），通常列 P2
資安
寫委託檔前先跑密鑰掃描 check-secrets.mjs --diff，加上相依套件弱點掃描，結果附在委託檔；有發現列 P0，不帶著密鑰送審

hd5-onsite-gate

驗收自動

站上關卡：部署到測試環境後、通知需求方之前，先確認站上跑的是這一版，再逐條操作到最終結果。

誰用
主對話
怎麼叫
上站驗一下送 PM 前檢查
產出
qa/onsite-gate_R{n}.md：A 表是驗收項目加證據，B 表是專案自訂的平台契約，最後一行是三態總結
把關
verify-map-check.ps1 -Onsite；沒通過就不能改「待驗收」

hd5-case-report

結案自動

結案報告：給下一張工單看的交接記憶。檔名固定、8 節固定，附 commit hash。

誰用
主對話；QA 和站上關卡都通過後產出
怎麼叫
寫結案報告交接
產出
AI_Service/spec/<案名>/ai-case-report.md；有工單系統時掛到來源工單
8 節
需求一句話、實際交付的驗收條件、改動範圍、關鍵裁定、測試與驗收結果、未盡事項、引用、給下一張工單的時效驗證
退回總帳
驗收退回和上線後才發現的缺陷（輪次寫「上線」、記回來源案）都記進 AI_Service/spec/rework-ledger.md，程式寫法類第一次就要有程式守衛

hd5-architecture

選配只有你能叫

架構健檢：從 git 熱點找出淺模組和架構摩擦點，做成候選卡片報告。你選定候選項後，再用質詢輪深挖到可以動工。

誰用
主對話；任何代理都不能自己啟動
怎麼叫
架構健檢哪裡該重構
產出
reports/architecture-review-{YYYYMMDD}.html、reports/grill-arch-{候選項}.md
重點
全程只規劃，不寫程式

角色與代理

角色定義只有一份，放在 .claude/agents/<角色>.md。Claude 把它當子代理派出去；Codex 沒有子代理，擔任某個角色時就完整讀那份檔照做。

角色代理做什麼主要用到的 skill
主對話（你正在對話的那個 AI）建案、判路線、派角色、把待決事項一題一題問你、合併、站上關卡、結案。不直接改產品程式；大量讀取交給子代理，只收摘要workflow、workitem、review、onsite-gate、case-report
PMpm-expert需求分析、驗收條件、質詢輪；體驗優先：寫出載入中／沒資料／失敗時的狀態，範圍太大時請 PO 決定先做哪幾項grill、spec-html、no-hallucination
SAsa-expert掃描專案、技術設計；小問題路線改做盤查，寫 sa/bug-analysis.md；設計質詢含「設計形狀」分支grill、no-hallucination、verify
實作workflow.json 的 implementers（預設 backend-expert／frontend-expert）TDD 加驗紅；修之前先列出同類位置；照代理檔的「程式設計原則」寫（先刪再加、檢查放邊界、不留舊 API）tdd、verify
QAqa-expert實作前先交測試計畫與會失敗的測試（Red）；實作後對照每個情境讀測試程式、測試報告、資安（順序：QA → 實作 → QA）；同一支測試修兩次還不對，先驗證前提再修tdd、verify
獨立審查者Codex，或全新的子代理唯讀審查整案的 diff 和行為證據review

會擋人的關卡

都在 AI_Service/hd5-tools/。Claude 由 hook 自動觸發；Codex 沒有 hook，派發前要自己跑質詢閘。

關卡工具什麼時候擋什麼
質詢閘validate-grill-gate.ps1派 SA／實作／QA 前沒寫路線、有路線卻跳步、小問題缺 SA 分析、高風險缺對抗輪、質詢紀錄沒收斂或還有待拍板題、PM 問卷沒有回收答覆、功能地圖不合格
派發 hookhooks/grill-gate.ps1Claude 每次派子代理prompt 指到某個案子時，自動呼叫質詢閘；放行也會回一行訊息（看不到＝hook 沒載入）
主對話改檔 hookhooks/main-edit-guard.ps1Claude 主對話每次改檔工作分支上有進行中的案子時，主對話改產品程式就擋，並建議該派誰（例外要你同意並寫進 spec_001）
功能地圖verify-map-check.ps1開工、站上關卡、工單閘地圖有佔位符、驗收項目對不到功能編號、Pass 沒證據
退回總帳check-rework-ledger.mjs改待驗收、驗收完成、上傳結案報告（工單閘自動跑）退回沒記進 rework-log、5.1 和總帳列數對不上、小問題寫了「逃逸：是」卻沒在總帳記「上線」那一列
密鑰掃描check-secrets.mjs送獨立驗收前；改待驗收時工單閘自動再跑diff 新增的行裡有私鑰、雲端金鑰、權杖、寫死的密碼或連線字串密碼（只印遮罩後的片段）
守衛對帳check-guard-refs.mjs每次跑守衛、新增 🔴 規則時🔴 規則沒有標「（守衛：…）」
導入把關check-onboard.mjs（在 hd5-onboard）導入結束時分支沒問、有待問題、舊規則沒有去向、產物被 .gitignore 忽略
工單閘workitem/_acceptance-gate.ps1改「待驗收」、上傳結案報告前缺獨立驗收結果、缺站上關卡報告、功能地圖不合格、Pass 沒證據、審過的 diff 裡有疑似密鑰
